# 小说智能可视化系统：开发需求规格 v1.0

> 状态：需求基线，供 Codex 开始设计和开发。日期：2026-11-13。
> 本文区分已确认需求、推荐实现与待验证事项；未经用户确认，不应将推荐方案视为不可变约束。

## 1. 项目定位

开发一个 **Windows 独立桌面软件**，将用户导入的小说文本解析为人物、服装、场景、道具等视觉资产，并利用本地或云端图像模型生成与原文段落关联的插图。**这是小说插图与视觉资产管理工具，不是视频分镜制作工具。**

核心原则：

1. **模型无关**：任何 AI 功能都可以单独选择模型/供应商，不绑定 DeepSeek、MiniMax H3-Image 或任何单一服务。
2. **本地与云端并存**：支持本地 ComfyUI 工作流、其他本地模型服务，以及各类云端 API；不得假定所有服务均使用 OpenAI 兼容协议。
3. **用户控制**：用户决定使用何种模型、何时提交任务、何时重试及是否产生付费调用。
4. **绝不自动故障转移**：任何 AI 调用失败后只展示错误与可选操作，不自动切换备用模型、不自动发起额外付费请求。
5. **原著忠实**：将原文明确事实与 AI 推断/补充设定分开保存；未描述的视觉细节由用户确认。
6. **视觉一致性**：通过结构化资产档案、参考图及版本记录保持人物面容、服装、道具、场景一致性；LoRA 为后续可选增强。
7. **本地数据可控**：优先将程序工作数据、模型工作流、缓存和项目资产放在 D 盘，避免默认大量占用 C 盘。

## 2. 典型工作流

1. 用户创建项目，导入 TXT、EPUB 或 DOCX 小说；保留原文、章节、段落定位。
2. 选择文本解析模型（例如 DeepSeek API、本地 LLM、其他供应商 API），解析全书或指定章节。
3. 提取人物、关系、外貌、服装状态、地点、场景、道具及重要事件，记录对应原文证据和来源位置。
4. 建立可编辑的视觉资产档案；明确区分“原文事实”“AI 推断”“用户确认设定”。
5. 选择某个段落或场景，生成候选插图任务；自动关联对应人物、服装版本、场景和参考图。
6. 用户选择提示词模型和图像生成模型/工作流，检查提示词、参考图及参数后提交。
7. 图像由本地 ComfyUI（例如 H3-Image）或云端图像 API 生成；可按用户指令执行图像编辑。
8. 用户审核、修正或重新生成；选定正式插图并绑定原文位置，保存所有生成历史和模型参数。

建议界面：**左侧小说/章节文本，中间场景解析与资产，右侧插图预览和生成控制**；另有模型管理、资产库、任务历史等页面。

## 3. AI 任务与模型选择

以下每个任务类别均应**独立配置首选模型**，且可在任务提交前手动改选：

| 任务类别 | 本地路径示例 | 云端路径示例 |
|---|---|---|
| 全书/章节解析 | 本地 LLM 服务 | DeepSeek、OpenAI、Gemini 等文本 API |
| 人物/场景/道具提取 | 本地 LLM | 任意适配的文本 API |
| 场景选择、提示词生成 | 本地 LLM | 任意适配的文本 API |
| 人物设定图、场景插图 | ComfyUI 图像工作流 | 各供应商图像生成 API |
| 图片编辑、多参考图 | 具备该能力的 ComfyUI 工作流 | 具备该能力的图像编辑 API |
| 视觉分析与质量审核 | 本地 VLM / 相应 ComfyUI 工作流 | 具备视觉输入能力的 API |
| 图片放大 | ComfyUI 超分工作流 | 可用的超分 API |

**能力必须按模型/工作流声明并校验**，不能假设所有模型支持图生图、多参考图、局部编辑、LoRA、任意尺寸或相同采样参数。模型示例不是兼容性保证。

### 3.1 模型管理

- 添加、编辑、禁用和测试连接：供应商原生 API、OpenAI 兼容 API、本地 ComfyUI、本地 LLM 服务（如 Ollama/LM Studio）。
- 配置服务地址、模型标识、密钥引用、超时、支持的任务类型和能力标签。
- 每类任务分别指定默认模型；支持保存“高质量/经济/快速”等**用户手动选择**的模型预设。
- 支持同一场景由用户主动选择多个模型进行对比，保存各结果、耗时、参数和已知费用。
- 记录每次实际使用的供应商、模型、工作流版本与生成参数，以便复现。
- API Key 不以明文写入项目数据库或日志；建议使用 Windows 凭据管理器或等效安全存储。

### 3.2 统一适配器设计（推荐）

对上层暴露标准任务接口，按能力区分：`text_generate`、`structured_extract`、`vision_analyze`、`image_generate`、`image_edit`、`upscale` 等。各适配器负责请求格式、上传素材、轮询、取消、结果获取及错误映射。

推荐：Python 后端；文本服务可评估 LiteLLM 或自定义适配器；图像 API 采用供应商专用适配器；ComfyUI 单独适配。**不要将所有图像服务强行抽象成完全相同的参数集合**；标准公共参数之外保留供应商扩展字段。

### 3.3 ComfyUI 自定义工作流

- 用户导入 **API 格式**的 ComfyUI 工作流 JSON。
- 允许用户将软件的提示词、参考图、尺寸、seed、步数、LoRA 等字段映射到指定节点及输入字段。
- 支持不同工作流各自独立保存映射配置，明确输出节点/产物读取方式。
- 可尝试自动识别常见节点，但**必须允许手动确认和修改**；不承诺自动兼容任意自定义节点。
- 执行前检查工作流必需参数；支持提交、状态轮询、错误显示、获取图片及用户取消。
- 不能因为本地工作流报错就自动转向云端 API。

## 4. 错误处理：已确认的强制要求

**明确排除“自动故障转移”功能。**

- 请求失败时显示可理解的错误：网络超时、API 权限/余额、限流、模型不存在、ComfyUI 节点失败、显存不足等；保留可复制的详细错误日志（脱敏）。
- **保留任务草稿**：原文位置、提示词、参考图、资产版本、已填写参数及此前成功的中间结果。
- 仅提供由用户触发的操作：`重试当前模型`、`手动切换模型`、`修改配置/参数`、`取消任务`。
- 切换模型时继承兼容的任务参数和素材；对不兼容项明确提示，不静默丢弃关键约束。
- 对超时但服务端状态未知的付费请求提示“可能已执行或计费”，避免无意重复提交。
- 不自动切换备用模型，不自动重新提交付费调用；后台状态查询（不触发新生成）可按任务需要进行。

## 5. 内容与视觉资产

### 5.1 原文与解析

- 保留原始文件、章节结构、段落 ID、字符偏移/定位信息；支持回看每条解析结论的原文出处。
- 解析结果结构化存储，建议 JSON Schema 校验；模型输出不合规时提示或由用户明确发起修复。
- 支持分章/分段处理长篇小说，并通过全局角色表和章节状态避免前后矛盾。

### 5.2 资产类型

- **人物**：身份、外貌、年龄阶段（仅原文允许时）、面容特征、关系、不同时间点的服装/装备状态、参考图。
- **场景**：地点、环境、建筑、天气、时段、风格与参考图。
- **道具**：名称、外观、材质、持有人、状态变化、参考图。
- **插图任务**：原文段落、参与人物、使用的资产版本、动作、构图、提示词、负面约束（若模型支持）、参考图、生成结果。

每条设定标记来源：`原文明确` / `AI 建议` / `用户确认`，并保留修改历史。用户确认后的设定优先于模型后续推测；原文事实与用户改编应可追溯。

### 5.3 一致性策略

第一阶段优先使用 **角色设定图 + 已确认参考图 + 结构化服装版本 + 场景资产关联**。人物初次出现时，可建议制作正面、侧面、全身设定图，但需要用户审核后才能纳入正式资产。不得默认认为单张参考图能完全解决一致性问题。

人物 LoRA 训练与管理为后续扩展，不纳入首版必做项；不要预设 H3-Image 某量化格式必然支持特定 LoRA 或训练流程，需实际验证。

## 6. 桌面界面与交互

建议 PySide6/Qt + Python：

- 项目首页：新建、打开、导入小说。
- 小说阅读与章节导航：选中文本创建场景/插图任务。
- 解析审核：原文证据、AI 提取项、人工修改与确认。
- 视觉资产库：人物、服装、场景、道具、参考图、版本管理。
- 插图工作台：场景信息、模型选择、工作流选择、参数、参考图、预览与编辑。
- 模型与连接设置：供应商、API、ComfyUI、能力声明、测试连接。
- 任务历史：状态、错误、耗时、费用（可获知时）、生成文件与复现参数。

界面须避免主线程阻塞；支持较长的解析/绘图任务和明确的取消操作。对于已提交的云端任务，取消是否能终止计费取决于供应商，界面须说明。

## 7. 技术与存储（推荐）

- 目标平台：Windows；优先使用 Python + PySide6，SQLite 存储项目索引和元数据，文件系统存储原文、图片和工作流。
- 推荐项目根目录：`D:\AI_Work\NovelVisualizer`，并允许用户自行更改。
- 用户可配置缓存、临时文件、日志和导出目录；尽可能避免默认大量写入 C 盘。
- 使用异步任务队列/后台工作线程，区分任务状态：`draft`、`queued`、`running`、`succeeded`、`failed`、`cancelled`、`unknown`。
- 项目可迁移：相对路径存储资产，导出/备份时保留数据库与资源文件；不把绝对盘符写死在项目引用中。
- SQLite 需要版本化迁移；任务日志须脱敏；保存生成参数、参考图版本和工作流哈希以便追溯。
- 可考虑模块划分：`ui/`、`core/`、`providers/`、`comfyui/`、`assets/`、`storage/`、`jobs/`、`tests/`。

## 8. 分阶段交付

### 第一阶段：最小可用版本（MVP，优先开发）

1. Windows 桌面主界面、项目创建/打开、数据目录可配置。
2. 导入 TXT/EPUB/DOCX，章节/段落索引及原文定位。
3. 可配置至少两类文本接入方式：一个云端 API（可先实现 DeepSeek）+ 一个本地 LLM/兼容服务；保留通用扩展机制。
4. 小说段落/章节解析、结构化人物/场景/道具档案、用户审核修改。
5. ComfyUI API 工作流导入、节点映射、提交与结果回收。
6. 至少一种云端图片 API 适配器作为切换示范（具体供应商由开发时确认）。
7. 场景插图工作台：提示词编辑、模型手动选择、参考图、生成/重试/取消、图片与原文关联。
8. 完整错误提示、任务状态及历史记录；**验证不会自动故障转移**。
9. API 密钥安全保存、日志脱敏、项目备份基本能力。

### 第二阶段：增强

- 多模型并排对比、批量场景生成（用户明确启动）、图片编辑与局部修正。
- 视觉模型辅助审核、人物一致性评估、资产版本差异。
- 更多供应商原生 API 与工作流预设；图像超分。
- 可选 LoRA 训练/管理接口（取决于实际模型生态与硬件验证）。
- 更完善的费用统计、任务导出、项目打包与迁移。

**不纳入首版**：自动故障转移、无人审核整本小说全自动生成、LoRA 训练、视频分镜制作。

## 9. 验收标准（首版）

1. 可以从小说原文选定段落，解析并创建资产关联的插图任务，生成结果能够准确回链到原文。
2. 文本解析模型和图像生成模型能够**分别选择**，至少演示本地/云端两类调用路径。
3. 用户能够导入一套 ComfyUI API 工作流、手动映射输入输出，并成功获取生成图片。
4. 失败时保留全部输入和已成功的中间结果；**绝不自动切换模型或发起第二次生成请求**。
5. 人物外貌与服装版本可编辑、锁定和引用；AI 推断与原文事实有明确标记。
6. 任务记录可查看使用模型、工作流、参数、参考图、时间及错误详情。
7. 工作数据目录可以设在 D 盘；不强制将项目资产保存在 C 盘。
8. 密钥不以明文进入项目导出包或普通日志。

## 10. Codex 开工建议

先不要一次性编写全部功能。建议按以下顺序交付可运行增量：

**里程碑 A：** 项目骨架、PySide6 界面、SQLite schema、可配置 D 盘目录、模拟任务执行与错误状态。

**里程碑 B：** 小说导入、章节/段落索引、结构化资产数据模型、人工编辑。

**里程碑 C：** 统一 AI 任务接口、文本 API/本地适配器、结构化解析与校验。

**里程碑 D：** ComfyUI 工作流导入/映射/执行、云端图像 API 适配器、插图与段落关联。

**里程碑 E：** 完整端到端测试、失败恢复、密钥保护、数据迁移与打包。

每个里程碑应提供：可运行程序、依赖说明、启动方法、测试结果、未完成项。不得以“支持某模型”为由硬编码整个产品的核心流程。

## 11. 尚待确认的实现细节

- 首版优先支持哪些 EPUB/DOCX 复杂格式特性（图片、脚注、排版）。
- 首个云端图像 API 供应商和首个本地 LLM 服务。
- DeepSeek 及其他供应商的具体 API 版本、费用获取方式和能力限制。
- H3-Image 当前可用的 ComfyUI 工作流、参考图/编辑能力及量化兼容性，需以实际环境测试为准。
- 首版是否需要内置安装包，或先以 Python 源码启动。

这些未确认项不应阻碍先完成可扩展的程序骨架。
